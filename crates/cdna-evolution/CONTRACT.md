# Evolution core contract

Pure serializable state machine; no database, filesystem writes, executable loading or automatic permissions. Parent persists the entire `Evolution` plus active pointer in one encrypted-store transaction with revision compare-and-swap.

`Evolution::new(workspace_id, input_revision, deletion_epoch)`; `register(candidate, artifact_bytes)` verifies SHA256 and the bounded supported model contract. `evaluate(candidate_id, signed_receipt, dataset, evaluator_key)` recomputes evidence hashes, checks trusted evaluator signature, held-out families/time, paired rows and measured thresholds. `approve(candidate_id, signed_approval, human_key)` verifies a distinct trusted human signature bound to workspace, epoch, revision, candidate/artifact/receipt hashes. `activate(candidate_id)` switches state and active pointer; `rollback(candidate_id)` accepts only previously approved, evaluated, still-current retired artifacts. `invalidate(new_revision,new_epoch)` quarantines all artifacts and clears active pointer.

Signing keys never live in this crate. Verification keys are supplied only by the trusted host, never accepted from the requesting agent. `signing_bytes(value)` is the deterministic serde JSON encoding used for signatures and content hashes; struct field order is fixed. Receipts/approvals carry signatures over their payload. Hashes are integrity bindings, not evidence of evaluator trust; the signature and host-controlled key are required. Deserialized state must be passed to `validate_restored` with current trusted keys and exact revision/epoch before use. Current revision/epoch remain the encrypted store's authority.

Allowed changes are model weights and bounded numerical inference support in feature version 1.0; executable code, permissions, providers and supply-chain changes are unrepresentable. Numeric evidence derives from signed paired case rows, not promotion booleans. All quality, latency, memory and learning-burden comparisons are measured on the same dataset. No Jev identity, benchmark, or superiority claim is represented.

After validation, `active_candidate()` returns the current bound model, and `active_domains()` returns the evaluated domain scope. The host must not use promotion as authority for unmeasured domains. Resource comparison is conservative nonregression, not a claimed measured improvement. Serialized restore validation disables active access on failure.

Executable feature-version 1.0 configuration can optionally carry `inference` metadata. Its canonical field order is `schema_version`, `slope`, `domains`, `valid_from_unix`, `valid_until_unix`, `min_margin`, `max_margin`, `missing_patterns`, `feature_min`, `feature_max`; this entire configuration, including weights, is hashed and approved together. Legacy configurations omit the field and remain verifiable, but cannot authorize learned ranking. Slope preserves the learner's `calibration.slope`: two-choice probability is `sigmoid(slope * (score_left - score_right))`, never an uncalibrated softmax. Domains intersect the signed evaluated test domains. Validity uses an inclusive Unix-second start and exclusive end, checked against host time and request context time.

Missing-pattern integers contain six attribute bits in extractor order (cost, effort, speed, reuse, customer_impact, irreversibility), followed by five context bits (deadline_pressure, asset_importance, loss_tolerance, customer_impact, budget_pressure). A set bit denotes absent input. Each candidate must have an explicitly supported complete 11-bit pattern. The 17 lower/upper feature bounds and absolute score-margin interval are evaluator-attested support, not defaults inferred by the runtime. Unknown attributes/facts, nonexplicit facts, unsupported units, range violations and unsupported patterns abstain. Human and evaluator signatures attest this configuration; the state machine does not invent empirical calibration measurements or generate signatures.

Python provisional artifacts are not executable approved candidates. Conversion must preserve weights, feature version, calibration slope/domain and selected abstention margin, while obtaining explicit independently validated context-pattern support, OOD bounds, maximum margin and validity period. The learner's candidate-only six-bit masks cannot be silently extended to all context patterns. Conversion does not grant evaluation, approval or activation.
