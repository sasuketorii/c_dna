# Store contract
`Store::create(path, &Zeroizing<String>)`, `open`, `lock` manage a SQLCipher vault. Keys must be high-entropy secrets supplied in memory, never CLI arguments. `create_workspace(Uuid)` establishes scope. `propose(workspace, id, request_id, Value)` always creates pending revision 1. `confirm(workspace,id,expected_revision,request_id)` is reserved for trusted local user interaction. `revise(workspace,id,expected_revision,request_id,Value)` creates a new pending revision. `get` and `list(workspace,limit,offset)` return `Record { workspace_id,id,revision,status,payload }`. `delete(workspace,id,expected_revision)` purges revisions, clears all workspace derivatives, and records tombstones. `epoch()` is the vault deletion epoch. `save_model(workspace,id,expected_epoch,Value)` / `model` hold encrypted derived models. `backup(path,recovery_key)` produces a separately keyed SQLCipher DB; `restore(backup,recovery_key,new_path,new_key,known_tombstones,known_document_tombstones)` restores only to a new file. `tombstones()` returns IDs to reconcile. `export_jsonl(workspace,limit,offset)` returns bounded sensitive plaintext in memory for explicit user export. Errors include Locked, RevisionConflict, NotFound, InvalidInput, RequestConflict, and typed storage errors. No public API accepts training eligibility or trust flags. Domain-specific payload validation belongs to the caller. Lists capped at 1000 and payload at 1 MiB.

`workspaces() -> Vec<Uuid>` lists scopes. `list_models(workspace,limit) -> Vec<(Uuid,Value)>` lists only current epoch models. `Status` is enum `Pending|Confirmed` with snake_case serialization. Every record mutation advances epoch and invalidates workspace models. On macOS `keychain::create(vault_id)` and `keychain::load(vault_id)` return `Zeroizing<String>`, using Security.framework. Unknown credentials never create automatically on load. Application must serialize vault creation for a given vault UUID. Database schema v1 has no upgrade path yet; unknown schemas fail closed. Snapshot/job persistence is not yet implemented. Backup is an encrypted SQLCipher database (not portable export); source remains intact on failure; backup/restore are prepared in same-directory encrypted temporary files, verified and closed before no-clobber publication to the final name. Historical request replay returns the immutable originally committed revision, not necessarily current head. No SSD erase guarantee is made.

## Durable grants (unreleased schema v1)
`Grant { id:Uuid, workspace_id:Uuid, scopes:Vec<String>, expires_at:i64, revoked:bool, token_hash:String }`. `expires_at` is UTC Unix seconds. `create_grant(&mut self, Grant)`, `authorize_grant(&self, token_hash:&str)->Grant`, `revoke_grant(&mut self,id:Uuid)`. Every authorization reads live expiry and revocation. Token hash is lowercase 64-character SHA-256 hex; raw token never enters store API. Grants never confer local human confirmation authority. Caller checks returned workspace and requested scope before every operation and again before sensitive results. Fresh grants must have future expiry and revoked=false. Revocation is idempotent and advances vault epoch on its first state change.
Grant allowlist: `decision:read`, `decision:propose`, `judgment:infer`, `learning:read`. Restoring a backup revokes every restored grant so old credentials cannot resurrect permissions. `set_workspace_name(id,&str)` validates nonblank <=256-byte control-free names; `workspace_details()->Vec<(Uuid,String)>` returns up to 1000 entries. Generic job persistence remains outside this increment.

## Internal structured documents
`DocumentKind::{Policy,Source,Assessment,Consent,Improvement}` serializes snake_case. `Document { id:Uuid,workspace_id:Uuid,kind:DocumentKind,revision:u64,payload:Value }`. `put_document(kind,w,id,expected_revision,payload)->Document` requires expected revision 0 to create; `get_document(kind,w,id)`, `list_documents(kind,w,limit,offset)`, `delete_document(kind,w,id,expected_revision)`. Limits match records: 1MiB payload, 1000 rows and 16MiB aggregate. This is an internal persistence boundary; host validates each kind and trusted approval. Each mutation advances epoch and invalidates workspace models. Source mutation/deletion cannot be exposed until host lineage cascade is implemented. Document content uses SQLCipher protection.

`DocumentTombstone { id,workspace_id,kind }` is returned by `document_tombstones()`. `restore` requires BOTH observation and document tombstone slices; no legacy restoration entry point exists. Grant scopes additionally allow `policy:read` and `profile:read`.

## Atomic import persistence
`insert_documents_batch(kind,workspace,Vec<(Uuid,Value)>)->BatchInsertResult { inserted:usize,skipped:usize }` persists up to 1000 new documents in one immediate transaction (1MiB per payload, 16MiB aggregate). Existing or tombstoned IDs, including repeated input IDs, are skipped without overwrite. Workspace existence is checked even for empty input. A successful nonempty insertion advances epoch once and invalidates workspace models once. Validation failure rolls back the entire batch. Caller must not split a claimed atomic import into multiple batches; oversized imports need explicit selection into bounded operations.

## Evolution derived state
`Store::EVOLUTION_DOCUMENT_ID` is reserved UUID `cdfa81ae-7c42-481b-a8bd-1f3387259351`. `put_evolution_document(workspace,id,expected_revision,expected_epoch,payload)->Document` accepts only that ID and persists kind `Improvement` with epoch+revision CAS in one transaction. It does not advance epoch or invalidate models. Generic document put/delete/batch reject the reserved ID for every kind. Restore discards this derived state. Application must validate stored payload's epoch/trusted keys when reading it; generic get is raw persistence, not authorization or freshness approval.
