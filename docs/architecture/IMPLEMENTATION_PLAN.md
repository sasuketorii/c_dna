# 実装と受け入れ

基準は `exec_plan/C-DNA_Requirements_v1.0.0_2026-09-21.md`。必須要件を削減しない。
作業分類: heavy / critical / scoped-source-write。対象は新規製品全体。

## 上位目的（ユーザーによる追加）

CEO-DNAを第一の用途として、速度・正確性・学習効率を改善し続ける共通基盤を作る。
用途固有のデータ契約と、学習・推論・独立評価・改善候補・承認・ロールバックを分離する。
比較対象Jevの正式な参照先は確認待ち。対象・データ・計算資源・cold/warm・
入力から結果までの測定範囲を固定するまで、優越性を主張しない。
横展開のためだけの抽象化は追加せず、第二用途の実証で再利用境界を検証する。

## 2026-09-22の優先順位・追加要件

ユーザー指示により公開プレイグラウンドの追加開発・公開検証を停止し、エンジンへ集中する。
公開済み資産は維持するが、体験の受入完了とは扱わない。

判断クローンはユーザーの回答・理由、エンジン、Codex／Claude Code等のLLMによる
標準の`withAI`対話学習で最適化する。高速判断は学習成果であり、学習中のLLM利用は中心機能である。
初期導入は要件§6.2の専用プロンプトを既存ChatGPT／Claudeへ渡し、既に蓄積した本人の
判断傾向・具体例・例外・不確実性を構造化して取り込む。推測を訂正し、重要な未知だけを追加で尋ねる。
LLMは不足条件・矛盾・判断基準の仮説を整理し、理由と逆転条件を対話で引き出し、
次の質問・表現改善・学習実験を提案する。本人回答の自動生成・確認済み化や評価基準の引き下げは行わない。
学習・独立評価・採用承認・ロールバックまでを一つの循環として接続する。

自然言語入力の最終目標は入力から結論・根拠・必要な確認までの短い待ち時間である。
構造化候補の採点時間だけを全体の応答時間と呼ばない。文章の意味理解と数値への変換は
独立した精度評価が必要であり、実験的な抽出adapterの存在を完成した自由文判断と扱わない。

## 所有境界と順序

1. `cdna-domain`: 入力契約、型、上限、方針評価。
2. `cdna-store`: 暗号化SQLite、リビジョン、削除、バックアップ。
3. `learner`: 対称ペア学習、時系列・family分割、独立評価。
4. `cdna-app`: CLI、上記の統合、ローカルサービスとMCP。
5. `apps/desktop`: 同じコアを利用するアプリとプレイグラウンド。
6. 否定ケース、統合、独立レビュー、実機確認、配布確認。

フロントエンドはバックエンドの操作契約が成立した後に接続する。
共有ファイルと知識台帳は統合担当だけが変更する。

## 採用判断

暗号・DB・MCP・学習・CLI解析は既存ライブラリを使う。
Rust rusqlite/SQLCipher、公式rmcp SDK、Python scikit-learnのAPIを採用候補とし、
依存解決と実行試験で固定する。独自実装は判断契約・学習適格性・境界制御に限定する。
公式確認先: https://docs.rs/rusqlite/latest/rusqlite/ 、
https://docs.rs/rmcp/latest/rmcp/ 、
https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html 。

## 完成判定

取り込み→本人確認→記憶→学習→推論→訂正→再学習→削除→復元を実行する。
`docs/release/requirements-status.json` は未検証から開始し、証拠が得られた項目のみ更新する。
合成データの回帰検証を本人の再現精度と表示しない。モデルを自動昇格しない。
プレイグラウンドの架空データは本人の保管庫と分離する。
署名・公証・最古OS・本人の独立回答・外部アカウントの実接続は独立した受入条件。
