# CEO・LLM・判断エンジンの統合方針

2026-09-22。ユーザーの指示と、Orca上のFable 5.1 low／Astra lowによる直接討論を統合した設計判断。実装の現在地と次の順序は [kickoff](../release/KICKOFF.md) を参照する。

## 中心となる循環

高速判断は、深い学習の成果である。LLMは学習時の標準の教師として、本人の理由・例外・逆転条件を引き出す。Pythonは表現・小型モデルの学習と評価、Rustは保存・権限・検索・ルール・高速推論、Mojoは実測で有効な数値演算を担当する。

```text
既存ChatGPT／Claudeに専用プロンプトを貼る
 → 判断傾向・具体例・例外・未知を取り込む
 → CEOが訂正する
 → LLMが反例・逆転条件・不足を質問する
 → 出典付き回答／方針／表現候補を保存する
 → Pythonが学習し、未使用の本人回答で比較する
 → 承認した成果をRust／Mojoで高速に使う
 → 誤り・未知・本人の訂正を次の対話へ戻す
```

既存要件§6.2の [専用プロンプト](../prompts/bootstrap-profile-ja.md) と [JSON schema](../../contracts/bootstrap-profile.schema.json) を入口とする。全文履歴やアカウント接続を必須にはしない。既存AIが参照できない情報はunknownとして持ち帰る。要約の取り込みだけで本人の判断を検証済みにはしない。

## 合意した統合点

| 境界 | 決定 | 現時点 |
|---|---|---|
| Bootstrap → teacher | 既存暗号化SourceのID・revision・共有許可を引き継ぎ、仮説として開示 | parser、CLI、共有・撤回、MCP profile接続を実装 |
| Teacher → CEO | 理由・最小の逆転条件・対立仮説を質問し、回答・訂正・スキップを受け取る | MCP質問提案と本人回答の保存を実装。実LLM対話品質は未受入 |
| CEO → learner | 本人回答とAI由来の仮説を区別し、familyと出典を維持 | 本人回答・理由・逆転条件を保存。意味を学習表現へ変換する経路は未完成 |
| 理由 → 表現 | 既存§8.1の型付きASTを再利用。辞書・抽出器・正規化・student・校正・lineageを一つの版へ束縛 | 17特徴量はbaseline。拡張bundleは次の実装 |
| 合成例 → 学習 | 確認済みTRAIN anchorを必須にし、別role・別重み・生成量上限・同一splitを適用 | 蒸留用学習経路は未実装。本人ラベルには数えない |
| Teacher → 評価データ | TRAINだけを開示。将来の再分割でも一度開示したfamilyを評価へ戻さない | 現在のモデルのTRAIN allowlistは実装。永続的な開示台帳と再分割防止は未完成 |
| 学習セッション → 失効 | 回答は即保存し、削除・訂正・共有撤回を即時反映。残りの問いは草稿revisionで再検証 | 現在は1回答で残りのbatchが失効。安全なrebaseは次の実装 |
| 学習済み成果 → 推論 | 対象domain、表現版、入力範囲、epoch、署名、承認を照合 | 17特徴・二案の数値入力に対する署名済み経路を実装 |

## 討論で修正した案

- 新しい独自DSLは作らず、既存の型付きASTを使う。
- セッション終了までepoch更新を遅らせる案は採用しない。草稿revisionと即時失効を分ける。
- 本番を「外部MCPだけ」と定義しない。画面かMCPかではなく、用途・承認・実行権限で分ける。
- `inferred`を少し動かしても順位が変わらないことだけで、本番判断を許可しない。推定範囲そのものや意味解釈が誤っている可能性を自然文から評価する。
- 利用者が開始した対話学習モードでは、暫定advisor回答を通常の学習材料として表示できる。仮定・出典・未検証状態を明示し、hard-ruleや未知概念で判断できない場合は具体的な確認質問を返す。
- LLMへの追加相談の回答はまず仮説として保存する。確認済みTRAIN anchorができるまで蒸留適格にしない。
- 蒸留あり／なしで不変にするのは評価例の構成・正解・分母。学習結果に応じて予測値は変わってよい。
- 小規模pilotの件数・coverage候補値を品質認証にはしない。本番の領域別評価ゲートは維持する。

## 完成を判断する実験

一つの判断領域から、既存AIのプロフィールだけを取り込んだ保管庫で対話を開始する。本人が「既存顧客の障害復旧なら即応する」と例外を訂正したら、理由を保存するだけでなく、次の質問と後日の未使用の言い換えへの判断へ反映されることを確かめる。対話で見せた例は独立評価に数えない。

測定は、CEOの回答分数・独立anchor数ごとの学習曲線、回答範囲と本人一致率、誤り・保留・訂正回数、入力から自然文回答までのp50/p95、LLMへ回った割合、CPU/RSSを分ける。固定17特徴、記憶検索、ルール、本人プロフィール付きLLMを同じ情報条件で比較する。Jevの対象と比較条件は未確定であり、優越性は未検証の目標である。
